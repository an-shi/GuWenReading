# 古文阅读器架构

最后更新：2026-11-16

## 1. 总览

古文阅读器采用“单应用 + 本地核心”架构：

```text
┌──────────────────────────────────────────────┐
│                Flutter 应用                  │
│  ┌──────────────┐      ┌──────────────────┐  │
│  │  响应式 UI    │◄────►│   Riverpod 状态   │  │
│  │ 桌面 / 移动   │      │   本地仓库/服务    │  │
│  └──────────────┘      └────────┬─────────┘  │
│                                  │            │
│                        ┌─────────▼─────────┐  │
│                        │   Dart 本地核心    │  │
│                        │ 导入/翻译/知识/检索 │  │
│                        │ 备份/AI 客户端     │  │
│                        └─────────┬─────────┘  │
│                                  │            │
│                     ┌────────────▼──────────┐ │
│                     │ SQLite + FTS5 + 文件  │ │
│                     │ 本机数据库/原始书籍   │ │
│                     └───────────────────────┘ │
└──────────────────────────────────────────────┘
```

没有独立后端、HTTP API、服务器进程、远程账户或数据库。

## 2. 代码分层

### 2.1 UI 层

- `app/lib/features/`：书架、书籍详情、阅读器、检索、知识库、图谱、时间线、任务、设置。
- `app/lib/app/shell/app_shell.dart`：宽屏使用 `NavigationRail`，窄屏使用底部导航。
- `app/lib/app/theme.dart`：暖色纸张主题、墨绿与黄铜色、宋体标题。

### 2.2 状态与仓库层

- `core/providers.dart`：数据库、服务与 AI 客户端依赖注入。
- `providers.dart`：书架、书籍、章节、批注、书签、任务、实体、事件、图谱、时间线等异步状态。
- `data/repositories/`：把本地核心包装成 UI 易用的仓库接口。

### 2.3 本地核心

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 数据库 | `core/local/app_database.dart` | 跨平台打开 SQLite、目录初始化、FTS 检测 |
| Schema | `core/local/schema.dart` | 全部业务表、索引与约束 |
| 导入 | `core/local/import_service.dart` | 文件落盘、去重、章节/段落/句子写入、索引 |
| 文档解析 | `core/local/document_parser.dart` | TXT/EPUB/DOCX/PDF 文字提取 |
| 文本处理 | `core/local/text_utils.dart` | 章节识别、段落合并、断句与置信度 |
| AI 配置 | `core/local/ai_service.dart` | 服务商/模型配置、密钥、提示词渲染、HTTP 调用 |
| 翻译 | `core/local/translation_service.dart` | 分批翻译、缓存、人工保护、候选审核 |
| 知识 | `core/local/knowledge_service.dart` | 实体/关系/事件抽取、审核、图谱、时间线 |
| 检索 | `core/local/search_service.dart` | FTS5 与 LIKE 回退 |
| 助手 | `core/local/assistant_service.dart` | 上下文构建、引用校验、会话保存 |
| 备份 | `core/local/backup_service.dart` | 备份 ZIP、导出、恢复、恢复前副本 |

## 3. 数据流

### 导入

1. 文件选择器读取字节，计算 SHA-256。
2. 按扩展名解析 TXT/EPUB/DOCX/PDF。
3. 原文件写入 `books/<bookId>/`，封面写入 `covers/`。
4. 章节、段落、句子写入 SQLite；句子保留段落内偏移与断句置信度。
5. 原文写入 FTS5 索引（不可用时使用 LIKE）。

### 阅读

1. 章节内容从 SQLite 读取，按段落排序。
2. 译文按 `sentence_id` 关联，不做滚动比例匹配。
3. UI 根据宽屏/窄屏提供双栏、交替、原文优先、逐句等模式。
4. 阅读进度写入 `reading_progress`；批注与书签直接写本地表。

### 翻译

1. 读取章节未译句子；人工译文永不覆盖。
2. 按字符预算分批，携带上下文构建提示词。
3. 调用本地配置的 AI 服务，解析 JSON 译文。
4. 新译文写入 `translations`；重新翻译已有 AI 译文时生成 `translation_reviews` 候选。
5. 更新句子状态、书籍统计与 FTS 译文索引。

### 知识抽取

1. 读取章节段落与句子证据。
2. 依次调用实体、关系、事件提示词。
3. 实体/提及/关系/事件/出处写入本地表，默认待审核。
4. 图谱按关系表构图；时间线按 `time_start_year` 排序，未知年份单独展示。

### 备份/恢复

1. `VACUUM INTO` 生成数据库快照。
2. ZIP 打包数据库、原始书籍、封面与清单。
3. 恢复时解压备份数据库，通过 `ATTACH DATABASE` 在事务中复制表数据。
4. 恢复前保留当前数据库副本，恢复后重建 FTS 索引。

## 4. 独立性

- 桌面端与 APP 各自持有数据库和书籍文件，不共享运行时。
- AI 服务由用户本机配置，网络只用于访问用户指定的 AI 接口。
- 跨设备迁移通过备份 ZIP，不使用自动同步或服务器。
- 删除应用数据目录即删除该设备全部本地数据。

## 5. 已知限制

- 扫描版 PDF 的 OCR 未实现。
- Windows 构建需要开发者模式。
- iOS 构建/签名需要 macOS。
- 关系/事件的人工创建与完整编辑 UI 仍可继续完善。
- FTS5 取决于平台 SQLite；不可用时检索自动降级为 LIKE。
